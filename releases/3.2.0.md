# PlexonUtility 3.2.0

PlexonUtility 3.2 is the premium GUI/UX release for the existing 3.1 runtime architecture.

## Highlights

- Rebuilt `/utility` as a compact 45-slot PlexonCraft control hub with restrained green → cyan framing and a clearer visual hierarchy.
- Added a player profile card with AFK state and live available-utility count.
- Expanded Feed, Heal, Ender Chest, AFK, Workbench, Trash, and Homes into state-aware action cards with explicit status, permission state, and click guidance.
- Added distinct `AVAILABLE`, `NO PERMISSION`, `FEATURE DISABLED`, `INTEGRATION MISSING`, `TEMPORARILY UNAVAILABLE`, and `ADMIN ONLY` presentation rules.
- Added a dedicated PlexonFamily integration-status GUI instead of dumping long integration lists into player chat.
- Added a concise help/information GUI covering availability states, PlexonHomes ownership, Trash safety, quiet feedback, and the no-polling integration model.
- Added an admin-only diagnostics GUI while preserving `/utilityadmin` for console and detailed command output.
- Added consistent Back, Refresh, Help, and Close navigation behavior across the Utility surfaces.

## Architecture preserved

- `PlexonCore.text()` remains the only MiniMessage/template renderer used by the GUI.
- `PlexonCore.gui()` remains the sole protected inventory router/session owner.
- No animation scheduler, per-player timer, recurring integration poller, or duplicate inventory listener was added.
- Dynamic player/plugin/version values are inserted through safe template values instead of being parsed as MiniMessage.
- `/trash` remains a normal writable disposable inventory and is not converted into a protected Core navigation inventory.
- PlexonHomes remains authoritative for home persistence, limits, safety rules, GUI behavior, and teleport behavior.
- The rank-friendly `plexonhomes.limit.<N>` and `plexonhomes.limit.unlimited` contract remains unchanged.
- The 3.1 quiet-feedback and AFK bossbar/actionbar/social behavior remains unchanged.

## Regression coverage

- Added deterministic tests for local feature availability precedence.
- Added integration-state tests for ready, missing, degraded, incompatible, and failed providers.
- Added explicit admin-only state coverage.
- Existing AFK, command, configuration, cooldown, feedback, integration, message, and placeholder tests remain part of canonical CI.
