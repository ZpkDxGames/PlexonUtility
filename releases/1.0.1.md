# PlexonUtility 1.0.1

PlexonUtility 1.0.1 is the stable repository closure of the accepted 1.0.1 RC line. It keeps the plugin deliberately narrow while promoting the completed utility and AFK work from prerelease state to a production GitHub release.

The repository-wide source checkup found no functional defect that justified changing the accepted gameplay/runtime classes, so the stable patch is intentionally limited to release and CI hardening.

## Included utility scope

- `/feed [player]`
- `/heal [player]`
- `/enderchest [player]` / `/ec`
- `/workbench`
- `/afk`
- `/utilityadmin diagnostics|reload`
- `PlexonUtilityAPI` feature/AFK read contracts
- PlaceholderAPI outputs `%plexonutility_afk%` and `%plexonutility_is_afk%`

## Reliability and behavior

- Strict configuration type/range validation remains in place.
- Config and message reload candidates are parsed before live references are replaced.
- Heal guards invalid/dead targets and invalid maximum-health values.
- AFK state remains ephemeral and UUID-keyed.
- AFK automatic timeout uses one shared bounded scheduler rather than per-player timers.
- Activity tracking uses low-cost block-coordinate movement filtering and thread-safe in-memory AFK state.

## Stable release hardening

- Promoted the Maven/plugin artifact boundary from `1.0.1-rc.2` to `1.0.1`.
- Normal Build CI now runs on `main` as well as branches and pull requests.
- Replaced version-specific one-off publish workflows with one generic stable release workflow.
- Stable publication is allowed only from `release/stable` when it points to the exact current `main` commit.
- Release verification requires Java 25 bytecode, Paper 26.2 metadata, required classes/resources, non-bundling of provided runtime APIs, a non-empty passing test suite, and a verified SHA-256 checksum.

## Compatibility

- Java 25 / class major 69.
- Paper API `26.2.build.121-stable`.
- PlexonCore API compatibility remains `>=2.0 <3.0`; the compile-time release boundary remains the immutable PlexonCore `2.0.0` artifact.
- PlaceholderAPI remains optional and provided at runtime.

Live PlexonCraft rollout remains a separate operational follow-up and is not required for this repository/source release closure.
