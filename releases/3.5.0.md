# PlexonUtility 3.5.0

PlexonUtility 3.5.0 expands the Core-native staff toolkit with bounded entity management, common player-administration controls, and truthful synthetic vanish presence while preserving every specialist Plexon Family ownership boundary.

## Admin Center 3.5

- `/utility` and `/utilityadmin` now enter a grouped 3.5 administration hub for authorized staff.
- Player Management provides deterministic online-player selection plus direct game-mode, Utility-managed flight, event-driven god mode, movement-speed, inventory, and legacy moderation/prison navigation.
- Inventory Management reuses the existing permission-separated live `/invsee` editor and adds a dedicated confirmation before clearing storage, armor, and offhand.
- Entity Management exposes cleanup and spawn workflows through Paper Dialog typed input rather than command strings embedded in GUI logic.
- GUI entity cleanup always previews matched/protected/removable counts and requires an explicit confirmation before service execution.
- Existing vanish, kick/ban, prison, diagnostics, family, and integration screens remain available through the established admin toolkit rather than being duplicated.
- Navigation remains on `PlexonCore.gui()` and typed inputs remain on Paper Dialogs; no new generic inventory listener or animation scheduler is introduced.

## Entity management

- Adds `/killall <category|entity> [radius|world [world]]`.
- Supported category aliases include hostile/monsters, passive/animals, ambient, aquatic/water, bosses, mobs, and all.
- Players can never be selected or removed.
- Named entities, tamed entities, villagers, armor stands, displays, plugin/NPC-marked entities, and bosses are conservatively protected by default.
- Boss removal requires the `bosses` selector or an explicit boss entity type.
- Radius cleanup is spherical and bounded by configuration; explicit world sweeps require a separate permission.
- Large command cleanups use actor-specific in-memory confirmation that expires after 15 seconds. A changed selector/scope replaces the previous pending action, confirmations are one-shot, and another actor cannot consume them.
- Entity cleanup uses direct removal rather than simulated combat, so it does not intentionally create normal loot, XP, or kill credit.
- Adds `/spawnmob <entity> [amount]` with Paper registry-driven spawnability checks, loaded-location safety checks, configurable blocking, and an absolute batch ceiling of 100.

`/spawn` is intentionally not registered by PlexonUtility. PlexonTravel remains authoritative for server/world spawn travel; PlexonUtility entity creation is `/spawnmob`.

## Player administration

- Adds `/gamemode <mode> [player]` with separate self/other authority.
- Adds `/fly [on|off] [player]` for Utility-owned survival/adventure flight; Creative/Spectator flight is never forcibly disabled.
- Adds event-driven `/god [on|off] [player]`; 3.5.0 keeps god mode restart-ephemeral and does not poll health.
- Adds `/speed <1-10|reset> [walk|fly] [player]` with safe Bukkit-range mapping.
- Adds `/clearinventory [player]`, clearing storage, armor, and offhand while auditing the number of occupied stacks removed.
- Adds `/anvil` through Paper's native anvil surface with vanilla anvil rules/costs left authoritative.

## Vanish synthetic presence

- Adds public `VanishStateChangeEvent`, fired only on a real visible ↔ vanished transition.
- Ordinary players receive a synthetic leave on vanish and synthetic join on unvanish by default.
- The actor and staff with `plexonutility.admin.vanish.see` are excluded from the ordinary synthetic audience by default.
- Repeated `/vanish on` or `/vanish off` calls do not rebroadcast synthetic presence.
- Real join/quit suppression for persisted vanished staff remains lifecycle-driven and avoids duplicate announcements.
- No fake `PlayerJoinEvent` or `PlayerQuitEvent` is dispatched. Synthetic presence is presentation only.
- The current PlexonChats public API does not expose synthetic connection-message rendering, so this release uses the configured PlexonCore `TextService`/MiniMessage fallback without compiling against PlexonChats internals. PlexonChats remains the preferred future formatting authority if its public API gains that capability.

## Architecture and performance

- No new permanent polling loop or per-entity scheduled task.
- Cleanup performs one aggregate scan of the selected world/radius.
- Spawn operations remain synchronous on the proper Bukkit/Paper context and never fan out chunk loads.
- Entity parsing, entity cleanup, entity spawning, player administration, the 3.5 GUI wrapper, and timed confirmation state are separated into focused services instead of growing the existing moderation switch.
- Core capability registration now advertises active entity-management, player-admin, synthetic-presence, and vanish-event capabilities.
- Existing `admin-data.yml` remains unchanged; optional god-mode persistence is deliberately not introduced in this release.

## Configuration and permissions

- Existing 3.4.x configuration remains loadable with additive defaults.
- `/spawnmob` maximums above 100 are rejected by configuration validation.
- Cleanup radius and confirmation limits are validated.
- Synthetic-presence audience is restricted to supported policies.
- New destructive/state-changing commands use explicit admin permissions, permission-aware completion, and aggregate audit records.

## Verification and publication gate

- Java 25
- Paper API 26.2 (`26.2.build.121-stable`)
- PlexonCore compile boundary 2.0.5
- Canonical verification: `mvn -B -ntp clean verify`
- Distribution verification requires the 3.5 admin hub, entity/player services, transition API, confirmation store, command descriptors, Java 25 bytecode, provided-API isolation, and an explicit check that PlexonUtility does not register root `/spawn`.
- Stable publication additionally requires `releases/3.5.0-runtime-smoke.txt` containing recorded `result=PASS`, `paper=26.2`, and `java=25` evidence. The release workflow refuses publication without that runtime proof.
