# PlexonUtility 3.5.0

PlexonUtility 3.5.0 finalizes the Core-native Utility/admin surface on exact PlexonCore 2.1.0. The release hardens AFK authority, rank-facing self permissions, Utility-owned flight, migrations/reload, destructive administration, persistence, prison teleports, and vanish presentation without taking ownership from specialist Plexon Family plugins.

## Core/runtime

- Requires exact PlexonCore 2.1.0 / Core API 2.1.
- Uses owner-scoped Core scheduling for AFK, flight reconciliation, and transient entity batches.
- Refreshes module capabilities after accepted reload generations.
- Publishes Utility degradation through Core module health for runtime-generation failure, missing expected AFK coordinator, and AdminDataStore persistence degradation.
- Keeps optional integrations non-critical.

## AFK and rank permission contract

- `plexonutility.afk.auto.bypass` now defaults false.
- Incoming ordinary damage does not reset AFK; outgoing player-caused damage does.
- Async chat transitions are serialized onto the primary/Core path.
- Public `AfkState` / `PlexonUtilityAPI#afkState(UUID)` provide stable AFK reason/activity-age information.
- Self `plexonutility.enderchest`, `plexonutility.fly`, `plexonutility.feed`, and `plexonutility.heal` default false.
- `/fly` self-use uses `plexonutility.fly`; other-target flight remains separately permissioned.

## Flight lifecycle

Utility flight now has a durable player-PDC ownership marker. Survival/Adventure flight that Utility owns is reconciled or revoked on explicit disable, permission/rank loss, feature/reload disable, quit, plugin disable, and stale unauthorized reconnect. Creative/Spectator and externally owned flight are not stripped.

God mode remains event-driven and restart-ephemeral.

## Configuration and reload

- Fresh `config.yml` uses schema version 1.
- Legacy/no-schema config migrates additively; future schemas are refused.
- Bundled `messages.yml` recursively defines the required message-string schema.
- Candidate config/message preparation is side-effect-free.
- Existing operator files are backed up before committed migration rewrites.
- Config/message migration persistence is staged as one transaction.
- Reload uses a generation/rollback model so a rejected later step restores the previous runtime instead of leaving mixed config/message state.

## Entity cleanup

`/killall <category|entity> [radius|world [world]]` preserves player exclusion and conservative entity protection.

Hardening in the final 3.5 line includes:

- confirmation bound to the exact UUID candidate plan;
- post-preview entities can never be added to a confirmed operation;
- execution revalidates selector, scope, and protection;
- actor-specific one-shot confirmation with expiry;
- `plexonutility.admin.killall.bypass-confirm` defaults false and is not inherited by `plexonutility.admin`;
- configurable preview-plan ceiling `max-candidates` (default 10,000), failing closed when exceeded;
- large operations process at most 40 planned candidates per tick through one Core-owned coordinator;
- WildStacker soft integration uses supported stack-aware removal and reports logical mob amounts;
- WildStacker API uncertainty fails closed instead of raw-removing a managed representative;
- no simulated combat/loot/XP/kill-credit behavior.

## Entity spawning

`/spawnmob <entity> [amount]` remains the entity-creation command; root `/spawn` remains owned by PlexonTravel.

- living spawnable types only;
- hard maximum 100;
- bounded safe-location search;
- already-loaded chunks only;
- at most 20 creations per tick for larger requests;
- one Core-owned coordinator and one aggregate result/audit.

## Clear inventory and invsee

- Other-player `/clearinventory` uses actor-specific timed confirmation and inventory fingerprint/revalidation; a material inventory change requires reconfirmation.
- Storage, armor, and offhand are cleared as one audited action.
- Existing 3.4 `/invsee` live edit/view semantics are preserved.

## AdminDataStore and prison

`admin-data.yml` migrates from schema 1 to schema 2 with a pre-migration backup.

Schema 2 stores the prison world UUID plus last-known world name. Persistence is revisioned and exposes current/persisted revision, dirty state, pending writes, last success/failure, retry count, and health. Writes are serialized through Core I/O with bounded retry/backoff; shutdown waiting is bounded.

Prison set/clear success is only reported after durable persistence. Prison teleport uses UUID-first world resolution and `teleportAsync`, with actor/target revalidation on completion.

**Rollback note:** because 3.5 can migrate `admin-data.yml` to schema 2, a rollback to 3.4 must restore the pre-3.5 Utility data backup rather than assuming JAR-only rollback compatibility.

## Vanish and presentation

Utility remains the authoritative vanish-state owner and never dispatches fake Bukkit join/quit lifecycle events.

A real transition fires `VanishStateChangeEvent`, then public `SyntheticPresencePresentationEvent`. An external presenter may render/broadcast and mark the presentation handled; otherwise Utility emits the configured Core TextService fallback. The default ordinary audience excludes vanish-aware staff. Duplicate same-state requests do not rebroadcast.

This is the compatibility surface intended for future PlexonChats presentation ownership without a hard Utility → Chats dependency.

## Essentials boundary

This release does **not** declare Essentials removable. PlexonHomes/Travel ownership, nick/kits/mail/economy needs, and hard plugin dependencies still require production closure. PlexonTravel remains root `/spawn` authority.
